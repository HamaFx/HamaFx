## ============================================================
## 1. OVERVIEW
## ============================================================

NexusTrade is a production-ready forex and crypto trading web application.
It uses live market data, AI-driven analysis via Google Gemini, real-time
charts, paper trading, and a premium dark-mode UI.

Stack: React 18 + TypeScript + Vite + Tailwind CSS + Zustand
Charts: lightweight-charts v5 (TradingView)
Data Charts: Recharts
Icons: lucide-react
Font: JetBrains Mono (numbers), system sans-serif (text)
No backend — fully client-side SPA with localStorage persistence.
Designed for easy backend migration (service abstraction layer).

## 5. API SERVICES
## ============================================================

### CoinGecko (Primary Crypto) — src/services/coinGeckoClient.ts
```
Base URL: https://api.coingecko.com/api/v3
Rate Limit: 10-30 calls/minute (free tier)
No API key required.

Endpoints used:
  GET /coins/markets?vs_currency=usd&order=market_cap_desc&per_page=25
    → Returns Asset[] with price, market cap, volume, sparkline
    
  GET /coins/{id}/ohlc?vs_currency=usd&days={1,7,30,90,365}
    → Returns OHLCV arrays for chart: [timestamp, open, high, low, close]
    
  GET /simple/price?ids={ids}&vs_currencies=usd&include_24hr_change=true
    → Returns simple price lookup
```

### CoinCap (Fallback + WebSocket) — src/services/coinCapClient.ts
```
Base URL: https://api.coincap.io/v2
WebSocket: wss://ws.coincap.io/prices?assets=bitcoin,ethereum,...
No API key required.

REST Endpoints:
  GET /assets?limit=25 → Fallback for CoinGecko
  GET /assets/{id}/history?interval=d1 → Historical data

WebSocket:
  Streams real-time prices for subscribed assets
  Auto-reconnect with exponential backoff (1s → 2s → 4s → max 30s)
  Updates marketStore.cryptoAssets prices in real-time
```

### ExchangeRate-API (Primary Forex) — src/services/forexClient.ts
```
Base URL: https://api.exchangerate-api.com/v4/latest/USD
No API key required (free tier).
Returns all major currency rates vs USD.

Frankfurter (Fallback + Historical):
  Base URL: https://api.frankfurter.app
  GET /latest?from=USD → Current rates
  GET /{date}..{date}?from={base}&to={quote} → Historical for charts
```

### Google Gemini (AI) — src/services/geminiService.ts
```
Base URL: https://generativelanguage.googleapis.com/v1beta
Model: gemini-2.0-flash
API Key: User-provided via Settings → stored in settingsStore
Rate Limit: 15 requests/minute, 1500/day (free tier)

Functions:
  analyzeMarket(symbol, price, indicators, recentPrices)
    → Returns: { signal, confidence, reasoning, risks, stopLoss, takeProfit }
    → Prompt includes RSI, MACD, BB, SMA values + price action
    → Falls back to rule-based analysis if no API key
    
  analyzeSentiment(headlines)
    → Returns: { score (-100 to 100), label, impact, themes, reasoning }
    → Prompt includes news headlines
    → Falls back to keyword-based sentiment if no API key
    
  generateChatResponse(messages, context)
    → Returns: string (AI response)
    → Context includes portfolio, positions, market prices, watchlist
    
  evaluateTrade(symbol, side, quantity, price, portfolioContext)
    → Returns: { riskRating, suggestion, reasoning }
    → Used in OrderForm "Ask AI Before Trading" feature
```

### NewsData.io — src/services/newsService.ts
```
Base URL: https://newsdata.io/api/1/news
API Key: User-provided via Settings
Categories: business, crypto
Falls back to curated sample articles (20 articles) when no key.
```


Every chat message includes:
- Current portfolio value and P&L
- Open positions with individual P&L
- Watchlist symbols
- Active alerts
- Live prices of mentioned assets
- Current page the user is viewing

- Market analysis: Rule-based multi-indicator confluence scoring
  (RSI zones + MACD crossover + BB position + SMA trend → weighted score)
- Sentiment: Keyword-based scoring (~50 weighted financial terms)
- Chat: Returns helpful message about adding API key

## 10. CACHING AND RATE LIMITING
## ============================================================

### Two-Tier Cache (src/services/cache.ts)
```
L1: In-memory Map (instant, lost on page refresh)
L2: localStorage (persists, 5MB limit)

TTL by data type:
  Market prices: 30 seconds
  OHLCV chart data: 5 minutes
  Forex rates: 60 seconds
  News: 5 minutes
  AI analysis: 5 minutes
  AI sentiment: 10 minutes

On API failure: Returns stale cache data (any age) as fallback
```

### Rate Limiting
```
Per-API budgets enforced client-side:
  CoinGecko: 8 requests/minute
  CoinCap: 20 requests/minute
  ExchangeRate-API: 5 requests/minute
  Frankfurter: 10 requests/minute
  Gemini: 10 requests/minute (well under 15/min limit)
```

### Error Fallback Chain
```
Primary API → Fallback API → Cached Data → Stale Cache → Error UI
Example: CoinGecko fails → CoinCap → localStorage cache → old cache → error banner
```

## 13. CUSTOMIZATION GUIDE
## ============================================================

### Add a New Crypto Asset
1. CoinGecko already returns top 25 — increase `per_page` param in coinGeckoClient.ts
2. Add to CoinCap WebSocket subscription in marketStore.ts

## 15. BACKEND MIGRATION GUIDE
## ============================================================

### Architecture: Service Abstraction Layer
Every data operation goes through a service function.
To add a backend, swap the implementation — UI code doesn't change.

### Current (V1 — Client-Side)
```
Component → Store → localStorage
Component → Service → External API (direct)
```

### Future (V2 — With Backend)
```
Component → Store → Backend API → PostgreSQL
Component → Service → Backend API → External API (proxied)
```

### Migration Steps
1. Create backend (NestJS/Express + PostgreSQL + Redis)
2. Create REST API endpoints mirroring store actions
3. Swap store persistence from localStorage to fetch() calls
4. Move API keys to backend environment variables
5. Proxy all external API calls through backend
6. Add real JWT authentication

### Creating a New Store
```typescript
import { create } from 'zustand';

interface MyState {
  items: Item[];
  addItem: (item: Item) => void;
}

export const useMyStore = create<MyState>((set, get) => ({
  items: JSON.parse(localStorage.getItem('nexustrade_myitems') || '[]'),
  
  addItem: (item) => {
    const items = [...get().items, item];
    localStorage.setItem('nexustrade_myitems', JSON.stringify(items));
    set({ items });
  },
}));
```

### Making an API Call with Fallback
```typescript
async function fetchData(): Promise<Data> {
  // Check cache first
  const cached = cache.get<Data>('cache_key');
  if (cached) return cached;
  
  try {
    // Primary API
    const response = await fetch(PRIMARY_URL);
    const data = await response.json();
    cache.set('cache_key', data, 60000); // Cache 60s
    return data;
  } catch {
    try {
      // Fallback API
      const response = await fetch(FALLBACK_URL);
      return await response.json();
    } catch {
      // Return stale cache
      const stale = cache.getStale<Data>('cache_key');
      if (stale) return stale;
      throw new Error('All sources failed');
    }
  }
}
```

### Error Handling in Components
```tsx
const [error, setError] = useState<string | null>(null);
const [loading, setLoading] = useState(false);

const loadData = async () => {
  setLoading(true);
  setError(null);
  try {
    await store.fetchData();
  } catch (err) {
    setError(err instanceof Error ? err.message : 'Failed to load');
  } finally {
    setLoading(false);
  }
};
```

## 17. KNOWN LIMITATIONS
## ============================================================

1. Client-side only — API keys visible in browser (use your own keys)
2. localStorage limit ~5MB — sufficient for typical usage
3. Data lost if browser storage cleared — no cloud sync
4. Alerts only work while app is open in browser
5. CoinGecko free tier: 10-30 req/min (may throttle on heavy usage)
6. Gemini free tier: 15 req/min, 1500/day
7. Paper trading only — no real money, no real exchange connections
8. Forex charts use daily data (no intraday for free forex APIs)
9. No social features (sharing, leaderboards) — requires backend
10. Single user per browser (multi-user requires backend auth)
